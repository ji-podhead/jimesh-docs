# Overview

JiMesh is an open, self-hosted AI infrastructure platform: a Go gateway that
exposes an OpenAI-compatible LLM API on top of user-curated model **chains**
(fallback/priority lists across providers), a dashboard for operating
projects, workspaces and containerized dev environments, and an enterprise
tier with Keycloak-backed identity, an OPA policy engine, a vault for
secrets, and per-workspace encrypted file storage.

This repository (`ji-podhead/jimesh-docs`) is the shared **public
documentation package** for that platform. It covers:

- **Gateway HTTP API** — the audited operator-facing reference
  (`content/api/API_DOCS.md`): HTTP `:19091` / gRPC `:19092`,
  ~176 routes kept honest against the gateway's registered routes by a
  mechanical drift audit.
- **Enterprise API specs** — static OpenAPI 3.0.3 documents under
  `spec/api/` (auth is publishable; the admin spec exists here for
  completeness but the built site is never published beyond Pages' own
  access rules).
- **Live gateway OpenAPI** — the Go gateway serves its own spec at
  `GET http://<host>:19091/openapi.json` (unauthenticated, GET only).
- **Scalar playground** — a static docs site (`src/index.html`,
  built into `dist/`) that renders any of the above via
  [Scalar](https://github.com/scalar/scalar) from CDN.

## Repo map

| Path | Content |
|---|---|
| `README.md` | package purpose, build instructions, consumer guide |

| `.github/workflows/pages.yml` | build `dist/` and deploy to GitHub Pages on push to `main` |
| `dist/` | build output (gitignored, regenerated by `npm run build`) |

## Source of truth

This package only re-publishes copies; nothing here is the primary home of
a spec. The gateway reference lives in the backend repo, the enterprise
specs live in the enterprise repo, and each snapshot is refreshed via the
drift-audit process described in [architecture.html](architecture.html).

## Credentials

This repo contains **no keys and no internal hostnames**. Only ports,
paths and placeholder hosts (e.g. `http://<host>:19091`,
`http://<INTERNAL_HOST>:19091`) are documented.
