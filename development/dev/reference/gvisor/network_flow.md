Verwende Code mit Vorsicht.📦 Key Components of the Network MapContainer Workload: The untrusted application issues network commands (like connect() or send()) as if it were talking directly to a standard Linux kernel. [1] (https://blog.yelinaung.com/posts/gvisor/)The Sentry & Netstack: The Sentry intercepts these commands. Instead of letting the host kernel handle the TCP/IP connection, Netstack manages all connection states, packet endpoints, and control messages completely inside user-space. [1] (https://gvisor.dev/docs/user_guide/networking/), [2] (https://en.wikipedia.org/wiki/GVisor)AF_PACKET Socket: Because the Sentry is sandboxed and restricted from opening standard host network sockets for security, it interacts with the outer world using one heavily restricted AF_PACKET socket. It reads and writes raw wire-level packets (including Ethernet headers) directly to the virtual interface. [1] (https://gvisor.dev/docs/architecture_guide/networking/)Host Virtual Ethernet (VETH): gVisor scrapes IP addresses, MAC configurations, and routing profiles from the standard VETH device generated by container engines (like Docker or CNI Kubernetes plugins). It mimics this exact configuration seamlessly inside the sandbox.
